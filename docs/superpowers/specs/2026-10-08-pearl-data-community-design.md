# Pearl 中文社区数据站设计

## 目标

建设 Pearl 中文社区的首个公开入口。首版聚焦一页式数据站：让初次接触 Pearl 的中文用户快速理解网络正在发生什么，也让已有挖矿、链上或 AI 经济研究需求的用户直接获取指标、趋势和计算口径。

“Pearl 文本”是同一站点的第二阶段内容区。本次不填充文本内容，只在顶部导航中保留入口并标为“即将上线”。

## 产品原则

- 一页完成从实时判断到历史分析：首屏显示实时或当日指标，向下滚动提供 7 天、30 天和可扩展历史趋势。
- 参考 hl.eco 的信息架构，而不复制其品牌、内容、配色或具体组件：采用极简顶部导航、主题化长页模块和“指标可追溯”的结构。
- 每项指标同时说明数值、来源、更新时间和计算口径。估算值必须标示为“模型估算”，不可与链上读取值混淆。
- 用中文解释数据，但保留 PRL、FDV、GPU、PUE、PoUW 等通行术语。

## 受众和核心路径

### 新用户

从首屏了解 PRL 价格、网络状态与“挖矿是否有利可图”；继续滚动后了解网络、链上和 AI 交叉数据。

### 进阶用户

通过顶部锚点跳到网络、挖矿、链上、估值或 AI 模块，查看趋势、来源和计算方法。

### 研究和传播者

通过方法区核对数据来源、更新时间及指标的计算口径，并在后续文本区获取中文解读。

## 首版信息架构

### 顶部导航

- 左侧：Pearl 中文社区标识和简短副标题。
- 中间：数据、网络、挖矿、链上、估值、AI、方法六个页内锚点。
- 右侧：文本（即将上线）和数据刷新状态。

### 首屏：实时总览

首屏回答三个问题：PRL 当前值多少钱、网络是否健康、挖矿经济性如何。

- PRL 价格和 24 小时变化。
- FDV 及相对 BTC FDV。
- 网络算力、难度、最近出块时间和出块目标偏差。
- 单枚模型成本、现价差和盈利状态。
- 数据更新时间、来源和模型估算提示。

首屏卡片只展示最关键的六到八项指标；点击或滚动进入相应专题，而不在首屏堆满数据。

### 01 网络脉搏

- 算力、难度、出块速度和供应进度。
- 7 天 / 30 天切换，未来可扩展全历史。
- 解释“读链数据”与“按供应曲线计算的数据”的区别。

### 02 挖矿经济

- 单枚 PRL 产出成本、现价、成本差和是否可盈利。
- 成本模型输入：电价、GPU 效率、PUE、硬件摊销、矿池费率。
- 首版默认采用公开或维护的假设值；输入不足时标明“待维护 / 模型估算”，而不伪造精确值。

### 03 链上实况

- 矿池份额、交易活跃度、转账分布和持仓集中度。
- 交易活跃与持仓需要索引、节点或区块浏览器数据时，首版显示可得部分并保留“数据建设中”状态。
- 所有链上数据可追溯到 API、节点或索引来源。

### 04 估值与价格

- PRL 现价、FDV、流通 / 最大供应说明。
- PRL FDV 与 BTC FDV 的相对比例。
- 价格和网络指标的 7 天 / 30 天对照趋势。

### 05 AI 交叉

- 开源模型 API 推理价格的可维护对照。
- 边挖边推的成本模型与假设。
- 用“数据来源 + 模型计算”明确区分外部公开数据和社区推导结论。

### 06 方法与版本

- 每个模块的数据源、更新时间、计算口径及可信度标签。
- 协议 GitHub 最新 release 与中文变更摘要的预留区。
- 通过“数据状态”说明哪些内容实时读取、哪些半自动、哪些需要人工维护。

## 数据分层和刷新策略

| 层级 | 内容 | 首版策略 |
| --- | --- | --- |
| 直接读取 | 网络算力、难度、出块、池数据、可取得的价格 | API 适配层读取并缓存，显示最后更新时间 |
| 半自动 | 供应进度、FDV、历史聚合趋势 | 从直接数据派生，标注公式与更新时间 |
| 模型估算 | 产币成本、盈利、边挖边推成本 | 独立参数和计算器，展示假设与估算标签 |
| 后续建设 | 交易活跃、转账分布、持仓、完整历史 | 预留区块和空状态，待节点 / 索引器接入 |

prlstats 是首版主要的数据参考和候选 API 来源；实现时必须在浏览器请求前验证每个实际 endpoint、返回结构、频率限制和跨域策略。对价格、链上浏览器和 GitHub 的补充来源，将在实现计划中逐项列明。

## 视觉方向

### 气质

“珍珠白中的轻微虹彩折光”：安静、精密、带一点 PoUW 与 AI 硬件的未来感。整体应更像社区研究刊物和数据陈列室，而非深色交易终端或加密项目官网。

### 背景资产

以用户提供的三张参考图为视觉来源，重制一张不含文字或商标的背景资产：

- 暖珍珠白基底。
- 很低饱和的蓝、粉、浅黄、淡紫不规则柔焦光晕。
- 局部极淡的细线与弧形轮廓，可作为低对比度纹理。
- 不重绘或保留原图片中的文字、标识、建筑或图形主体。

背景用于首屏和关键分区的渐变过渡；内容区保持足够对比度，并可在窄屏降级为纯 CSS 的柔和渐变。

### 排版和组件

- 大留白、细分隔线、短标签配合大数字。
- 数据卡片使用半透明暖白底、柔和边线和极轻阴影，避免玻璃拟态的强反光。
- 说明性文字使用中文易读的衬线 / 无衬线组合；数字使用等宽或半等宽样式以提高扫读效率。
- 图表采用低饱和中性色和单一强调色，不把虹彩背景用于数据编码。

## 技术边界

- 首版采用本地可运行的前端项目，全部源码与资产保存在 `D:\pearl web`。
- API 请求经单独的数据适配层处理，页面组件不得直接依赖某个未验证的外部 endpoint。
- 页面先以内置示例数据保证布局完整；数据源可用时切换到实时读取，并在失败时保留可解释的降级状态。
- 首版不包含登录、钱包连接、交易、用户上传、评论或任何需要持久化的功能。
- 响应式优先：桌面为宽幅长页，移动端保持锚点导航、关键实时卡片和趋势图的可读性。

## 验收标准

- 用户可在一页内从实时总览滚动至全部数据主题和方法说明。
- 数据卡片明确标注最后更新时间与读取 / 推导 / 模型估算状态。
- 网络、挖矿、链上、估值、AI 和方法六部分均有完整页面位置和明确空状态。
- 视觉上使用独立的珍珠白虹彩背景，不含参考图中的文字、品牌或建筑元素。
- “文本”入口存在但不与数据站首版内容混淆。
- 项目可在本地构建并在桌面与移动宽度下正常浏览。

## 不在首版范围内

- 完整 Pearl 文本库及编辑系统。
- 区块链全量索引器和历史数据仓库。
- 账户、钱包、交易、收藏、评论或社区投稿。
- 对 prlstats 全部页面或全部模型的一比一复刻。
