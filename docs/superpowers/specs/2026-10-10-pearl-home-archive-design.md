# Pearl 首页与项目档案入口设计

## 目标

将当前网站的根路径 `/` 从数据看板调整为「Pearl 是什么」导读首页。首页以用户已整理的入门总述为主体，让访客先理解 Pearl 的机制与技术边界；原有实时数据看板迁移至 `/overview`，所有既有链上和 PRL 数据页面保留。

## 信息架构

```text
/             Pearl 是什么（新首页 / 档案 01）
/overview     数据总览（当前首页实时看板）
/chain        链上实况
/valuation    PRL 数据汇总
/archive      项目档案索引（后续六篇内容的入口）
```

顶部导航不单独加入「Pearl 是什么」，因为它就是首页。导航为：`数据总览`、`链上`、`数据`、`项目档案`。在本次范围内，「项目档案」可以先显示即将整理的六个专题入口，不要求同步完成其余五篇正文。

## 首页结构

### 首屏：一句话定义与探索入口

使用左右两栏布局：

- 左栏：档案编号 `01 / START HERE`、标题「Pearl 是什么」、一句话定义“Pearl 是一条 PoW 区块链，旨在让 AI 计算负载参与挖取原生代币 PRL。”，以及两个主入口：「开始阅读」滚动到正文、「查看数据总览」进入 `/overview`。
- 右栏：四张可点击的主题卡片，分别跳至页内章节：`Duplex Work`、`挖矿如何嵌入计算`、`Pearl-GEMM`、`两套里程碑`。卡片呈现编号、简短问题和向下/跳转箭头。

### 正文：可探索的档案长页

完整保留用户提供的正文逻辑，但改造成五个带锚点的模块：

1. 核心定位与工作原理；
2. 一份负载，两种产出（Duplex Work）；
3. 挖矿是如何嵌入计算的；
4. 从整数到 Pearl-GEMM；
5. 两个方向、两套里程碑与总结。

“准备 → 计算 → 检查 → 返回”使用流程视觉呈现，不以代码块作为唯一表达。桌面端正文边缘提供章节进度导航；移动端改为顶部横向章节条。

### 证据与边界

为避免将技术愿景、公开机制和实测事实混为一谈，关键段落旁添加三种非交互标签：

- `公开机制`：公开材料可解释的协议与流程；
- `团队表述`：团队公布但尚无独立复核的性能或时间预期；
- `待验证`：主网状态、第三方基准或尚未证明的功能边界。

页底提供「进入数据总览」「查看链上实况」与“下一份档案”的关联阅读入口。所有已有数据页面只改变入口地址，不改变数据来源、缓存与刷新逻辑。

## 视觉与交互

- 延续现有珍珠白背景、Fraunces 标题与 Instrument Sans 正文，不复制 Pearlified 的侦探叙事或视觉元素。
- 首屏保留数据站的克制感；右侧卡片采用低饱和珠光边缘，悬停仅展示轻微位移与底色变化。
- 内容中的流程、标签和相关阅读卡保持高对比度，移动端按单列阅读。
- 路由需支持浏览器前进/后退；从旧 `/#overview` 访问时，继续在首页内定位到 `/overview` 数据看板或提供兼容跳转，避免既有书签失效。

## 验收标准

1. 打开 `/` 时首先看到「Pearl 是什么」和一句话定义，不显示实时 K 线。
2. 首屏右侧四张卡片可以准确跳转到对应正文模块。
3. 「查看数据总览」和顶部「数据总览」均打开 `/overview`，并完整保留当前实时数据功能。
4. `/chain` 与 `/valuation` 的功能、数据读取及刷新规则不变。
5. 正文明确区分公开机制、团队表述和待验证边界；不把团队性能宣称写成已独立验证的事实。
6. 桌面与移动端均可顺畅阅读，且现有测试、构建继续通过。
