# Pearl 链上数据子页设计

## 目标

将当前首页中的链上摘要升级为独立的 `/chain` 页面。顶部“链上”导航进入子页；首页只保留少量链上摘要和一个跳转入口。子页按数据语义组织为网络概览、Pools、Activity、TX Size、Holders 五个区域。

## 页面与导航

- `/`：继续展示 Pearl 首页数据总览。链上摘要卡保留，新增“查看全部链上数据”链接至 `/chain`。
- `/chain`：使用浏览器 History API 在同一 React 应用内渲染，无新增路由依赖；刷新或直接访问 `/chain` 必须可用。
- 顶部导航的“链上”使用 `/chain`，在子页标识为当前项；其他导航仍回到首页锚点。

## `/chain` 信息结构

1. 网络概览：高度、难度、算力、出块时间、供应、排放、活跃持币地址。
2. Pools：矿池名称、24 小时出块数、份额、费率、结算方式；按日期展示历史出块/归因序列。
3. Activity：每日 TX、链上转账额、交易费、速度、新地址与活跃地址；展示 coin age 分层。
4. TX Size：统计摘要（笔数、总额、中位数、最大值）、巨鲸分档、每日分位数、金额分布。
5. Holders：持币地址数、已统计持币量、Gini、Top 1/10/100 占比、Top 地址表、新挖币首次移动时间分层。

## 数据与口径

所有数据经现有 Vite 代理读取，避免浏览器跨域限制。每个区块独立请求与容错，任一接口不可用时仅显示该区块的“暂不可读取”，不会阻断其他区块。

- `/api/home`：节点网络快照与市场参考。
- `/api/pools`、`/api/pools/history`：矿池的当前和历史归因。
- `/api/series?...`、`/api/coinage`：链上活跃度和币龄。
- `/api/txsizes?range=30d`：交易金额分布及摘要。
- `/api/holders`、`/api/mined`：持仓集中度、Top 地址与新挖币移动。

展示时会保留“prlstats 链上索引”来源标签，并在 Pools 与 Holders 中说明归因边界：未知矿工归入 `Solo / unknown`；Top 地址仅是公开 API 提供的前 100 名；币的移动不等于卖出。

## 交互与性能

- 页面初次进入并行读取五组数据。
- Pools 历史默认展示最近 30 天；TX Size 默认 30 天。
- 表格仅渲染 API 返回的 Top 100 地址，不额外拉取逐笔数据。
- 数字格式使用现有 PRL/USD/百分比格式化函数；不引入重量级图表库。

## 验收

- 导航“链上”进入 `/chain`，浏览器前进/后退和刷新均保持正确页面。
- 五个数据区域均可独立加载或显示错误态。
- 页面明确标识来源与计算边界，且不把地址移动描述为卖出。
- 为路径切换、链上页面模块及关键字段转换补充测试。
