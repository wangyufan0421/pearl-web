# Pearl vs Bitcoin 独立数据页设计

## 范围与取舍

在现有网站增加 `/pearl-vs-bitcoin` 子页，导航文案为 `Pearl vs Bitcoin`，紧跟“数据概览”。沿用现有中英双语、浅色珠光背景、细边框、玫瑰与蓝色数据色。只修改本地仓库，不创建新站、不部署。现有市值比例和 PEARL/BTC 价格序列可在新页引用，但不从估值页移除。

本页采用现有 prlstats 公共序列、由本站后台定时采集并持久保存。方案优于嵌入外站页面（无法保证样式和数据状态），也比立即重建完整 Bitcoin 硬件模型更适合当前范围。新增序列：`prl_energy`、`btc_energy`、`energy_vs_btc`、`prl_machines`、`btc_machines`、`prl_capex`、`btc_capex`、`prl_issuance_usd`、`btc_issuance_usd`。这些模型序列每 15 分钟尝试更新一次，不由访客直连 prlstats；已有 BTC 相对价格和市值序列继续复用。

## 页面信息架构

1. 标题说明：Pearl 和 Bitcoin 的哈希算法不同，不能直接比较 H/s。这里比较能换算成同单位的功耗、设备数量、硬件重建成本和发行价值；设备数与成本是模型估算，不是实际设备普查。
2. 顶部三项：Pearl 功耗占 BTC 的比例、Pearl 模型功耗、Bitcoin 模型功耗，均显示各自最近观测日期和数据状态。
3. 主图：`energy_vs_btc` 历史曲线，横轴时间、纵轴百分比；30D/90D/ALL 切换，鼠标、触屏和键盘聚焦可查看对应日期与数值。
4. 四组并列对照：两网功耗、等效前沿设备数、硬件重建成本、每日新发行币的美元价值。每组两条各自标注尺度和来源时间的历史小图；不要在同一个未经说明的坐标轴上叠加相差巨大的值。
5. 页尾显示现有 PEARL/BTC 价格、市值/BTC、FDV/BTC 链接或简洁卡片，并链接 prlstats 的方法页。顶部与图表展示最新可用快照的状态；缺失时给出明确空状态，绝不编造数值。

## 数据与交互边界

后台白名单、类型校验与前端加载器均扩充上述九条序列。历史图只对真实时间戳和有限数值作图；高频序列在前端按时间桶保留末次观测点，以免 1 万多点压垮浏览器。选择 ALL 时保留完整时间跨度，不把 BTC 的最后观测值延长到未来。所有“最新”都按每条序列各自的真实时间给出，避免把不同时间的数字称为同一时刻。

数据缺失或过期时遵循既有 `DataResult` 状态，不用假设或本地伪造样本补空。公共接口仍读取已保存快照。翻译文案进入现有词典；中文界面允许英文品牌名 `Pearl vs Bitcoin`。响应式移动布局把并列图折成纵列，保持按钮可点击、图表可读。

## 验收

- 导航顺序与中英文路径正确，`/en/pearl-vs-bitcoin` 可访问。
- 新增九条模型序列能从现有采集/快照 API 读取；错误响应不冒充成功。
- 百分比、MW/GW、设备数、美元值单位正确，时间范围与悬停数据一致。
- 现有站点页面、原有数据采集和导航不受影响；自动化测试和生产构建通过。
- 外部模型方法、估算性质和不同数据更新时间清晰可见。
