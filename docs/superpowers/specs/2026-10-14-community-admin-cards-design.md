# 社区讨论后台卡片改版

## 页面与操作

- `/admin/community-discussions`：密钥验证后展示讨论卡片网格。每张卡片包含标题、主题作者头像与 @账号、正文摘要、回应数量、进入管理和删除按钮。顶部加号进入新建页。
- `/admin/community-discussions/new`：左侧填写主题帖链接及可选标题、简介；右侧填写辩论/引推链接（一行一条，可留空）。提交后先保存主题，再逐条添加回应，显示失败结果并允许重试；若主题已创建、回应失败，不再次创建主题。成功后进入该讨论管理页。
- `/admin/community-discussions/:slug`：左侧展示已保存的主题帖及原文/中文译文切换、作者账号头像和刷新功能；右侧添加辩论/引推，并展示已添加回应及抓取结果。
- 页面内跳转保留内存中的管理员验证状态；退出或整页刷新后重新验证。直接访问新建或管理地址也必须先验证。
- 中文和英文后台都提供相同操作；手机端两栏顺序堆叠。

## 删除语义

用户已选择同时提供隐藏与彻底删除。卡片提供独立操作：隐藏后整组讨论从公开页面及正常后台列表隐藏，主题、回应和译文仍保存在数据库。后台提供隐藏筛选与恢复操作。彻底删除需要在确认框输入该讨论的地址标识，删除主题、回应及译文且不能恢复。

复用已有 draft 状态表示隐藏，published 表示公开；不需要数据库迁移。隐藏讨论不再参与新的翻译扫描，已在执行的请求可能完成；恢复后未完成译文继续处理。永久删除通过删除 discussions 的单条 SQL 操作及已有 on delete cascade 在同一事务内删除关联来源。

## 接口与一致性

管理员列表、详情、删除、恢复接口均在服务器验证密钥；公开接口仅返回 published 内容。新建保留现有抓取、去重和自动翻译流程。删除/恢复更新后台列表，讨论 API 使用 no-store，避免旧公开响应缓存。新建失败保留输入；主题保存成功后回应请求不确定时转入已存在主题的管理页继续处理，不重复创建主题。

## 验证

覆盖未验证访问、卡片导航、新建部分失败不重复创建、删除取消/确认、归档公开不可读、恢复、译文与原文保留。运行相关接口和 UI 测试及生产构建，浏览器检查桌面和窄屏两栏布局。

## 方案选择

推荐三页结构配合可恢复删除，直接对应用户所述导航。备选是在同一页用弹窗创建和编辑，跳转较少但长文章阅读及多条链接操作容易拥挤；永久删除更简单，但误操作后无法恢复。
