# 社区讨论管理员页面

用户确认通过网页粘贴主文章与回应链接、点击添加。沿用已有管理员 Bearer Token、Twitter241 抓取与 Supabase 快照，不增加账户系统。

入口 `/admin/community-discussions`，英文 `/en/admin/community-discussions`。社区讨论页提供小型管理入口，管理员页面不放进公共主导航。页面使用共享导航和双语文案，并设置 noindex 元信息。

页面首先要求输入 COMMUNITY_ADMIN_TOKEN，使用受保护 GET 验证令牌，不依赖数据库或消耗 Twitter241 请求。验证成功后令牌只在页面内存中保存，不写入 URL、日志、localStorage 或 sessionStorage；退出、离开页面或刷新后重新输入。所有写入仍在服务器端验证令牌。Twitter241 和 Supabase 密钥不进入网页。

第一张表单输入主文章 X status 链接，可选备用标题、简介和稳定 slug；点击“创建并发布讨论”触发抓取并公开保存。此版本不提供草稿工作流，因为当前后端尚无草稿发布接口。成功后显示详情入口并自动选择新讨论。

第二张表单从已发布讨论中选择对象，粘贴一行一个回应链接，每次最多 50 条。提交结果逐条显示 status ID 与新增、重复或失败状态。失败条目可调用已有刷新接口重试；选中讨论也显示已保存来源及刷新按钮。原始正文保留原语言。

所有操作需显示进行中状态，防止重复提交。401 清除会话并提示重新验证；错误只显示安全的界面说明。网络失败不自动重试写入，提示检查讨论页后重试。旧请求在退出后不能重新恢复会话或把结果显示在另一个讨论下。

读取已发布列表与详情使用现有公共 API，创建后或添加后重新读取。公开页面已有焦点及 60 秒刷新。无云端配置时管理员页面仍可打开，但真实验证、抓取和存储依赖部署环境变量。实现和测试不写入真实云端数据库。
